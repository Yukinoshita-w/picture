# 系列功能分步修改计划

制定日期：2026-10-22  
状态：0.1 至 5.2 已实施。第五阶段 5.1、5.2 已交付原文范围预览、章节／片段选择、完整摘录与来源回查、分段摘要及缓存重试、来源顺序校验和确认后追加大纲，并通过第五阶段专项核心与真实浏览器本地模拟验收。数据库仍为版本 1，导出包仍为版本 3，兼容版本 1、2。当前仓库缺少通用测试入口引用的历史测试文件，不能声称本轮完整回归通过。下一项为 6.1：增加图片联系表视图。详见 `docs/系列功能实施记录.md`。

## 1. 目标和实施方式

同时支持三类用途：连续故事／分镜／绘本，同角色／同风格图集，产品／海报批量变体。三类用途共用系列、素材、画面、生成记录和参数；通过适合各自任务的视图与预设展开。

实施单位是下面编号的小步骤，不是整个阶段。每次完成一个步骤，报告实际变化、验收结果和遗留问题，再决定下一步范围。发现影响数据完整性的新问题时，先调整计划，不顺带扩展功能。

首轮完成 **0.1 测试基线** 和 **1.1 单帧生成隔离**；第二次交付完成 **1.2a 读取与上传**、**1.2b 模型操作**。后续仍按编号逐步交付，不把本计划视为一次性重做任务。

基本约定：

- 保持现有页面风格，前期沿用大纲、矩阵、图库、圣经、档案入口。
- 沿用原生 JavaScript、现有生成接口和 IndexedDB，不在本轮更换前端框架。
- 新功能尽量采用新增字段和兼容读取，避免为了调整界面先迁移全部数据。
- 涉及存储结构升级时，单独列出迁移、旧数据验证和失败恢复步骤。
- 生成流程改动使用本地模拟服务验证；模拟测试不能证明真实模型的一致性与画面质量。
- 保留现有画廊独立副本与白板独立副本的关系；系列修改不得破坏已收藏和已放入白板的作品。

本计划细化此前 `docs/优化计划.md` 中的系列相关部分；其他页面的优化不纳入本次系列实施范围。

## 2. 检查基线与已确认的问题

本次检查时，116 项自动测试通过。`tests/series_smoke.py` 在画廊联动步骤因旧 `.gallery-album` 选择器中断，当前实现已经使用 `.gallery-set`。中断后的场景尚不能算作验收通过。

已复现：

1. A 系列开始生成后切到 B，返回图片写进 B，B 的内存列表还会混入 A 的帧。
2. 风格字段尚未保存新版本，改动已经参与提示词编译，版本号没有变化。
3. 只改变时间、景别等 `axisValues`，最终提示词可能完全相同。
4. 三个变量轴合计 1,152 种组合时，目前只统计到中途的 576 种，返回的组合缺少最后一轴。

代码中另有以下待修复项：重生成直接删除旧图，系列参数实时读取创作页，档案拆帧只读取每条前 4,000 字，批次缺少持久化恢复，导出提示包含提炼缓存但导出包没有对应内容。

**验收**：`npm test` 通过；系列浏览器测试跑到结束。若遇到新产品缺陷，记录最小复现场景，不删除断言掩盖失败。

## 4. 阶段一：保证任务和数据归属正确

### 1.1 修复单帧生成期间切换系列的问题

**改动范围**

- 请求启动时固定系列 ID、帧 ID、提示词、参考图、风格版本和实际请求参数。
- 返回结果按任务归属保存，不再读取此刻打开的系列作为保存目标。
- 仅在当前仍显示该系列时更新其列表、详情和状态提示。
- 同一帧生成中禁止再次提交；任务进行期间，暂时禁止删除所属系列和目标帧，避免迟到结果重新创建已删除内容。
- 保留当前串行生成方式，不同时加入并发队列。

**验收场景**

1. A 开始生成，切到 B；图片只属于 A，B 的数据和界面不被污染。
2. A 请求失败时，B 不出现 A 的错误帧。
3. 生成中修改设置，返回结果仍记录启动时的条件。
4. 关闭详情、切页面和返回系列，不改变任务归属。
5. 连续点击生成只发出一次请求；相关删除操作有明确的进行中状态。

**涉及位置**：`public/series.js` 的生成、保存和状态更新；必要的存储方法。

**完成条件**：以上场景有可重复的模拟浏览器验证。此步是第一项功能修复。

### 1.2 处理其他异步操作的系列隔离

拆成两个独立小交付：

- **1.2a 读取与上传**：快速切换系列时，只应用最后一次打开操作的结果；上传、压缩完成后仍写入启动时的系列。
- **1.2b 模型操作**：提炼、拆帧、单帧扩写和看图返回后，只修改所属系列及目标记录；目标已删除时不重新创建。

**验收**：分别在操作中途切换、删除目标或关闭对话框，确认不会串项目、混入列表或用旧响应覆盖新选择。关闭对话框后的任务状态要明确。

### 1.3 保证一次生成结果完整落盘

**改动范围**

- 图片资源和帧结果关联使用同一事务提交。
- 提交失败保留原有采用结果，不提前删除旧图。
- 远程 URL 出图通过现有服务下载为本地资源后再标记为已保存；下载失败保留待保存状态和重试入口。
- 处理远程图片保存作为本步的第二个小交付，先完成事务一致性。

**验收**：模拟空间不足、事务失败和图片下载失败，原图不丢失，不出现“已完成但图片不存在”；保存成功的图片刷新、断网后仍可查看。

**前置**：1.1。此步不引入完整候选管理。

## 5. 阶段二：让矩阵生成确实产生不同画面

### 2.1 让变量值进入提示词

**改动范围**

- 把帧选择的变量名称和值明确编入提示词。
- 先支持现有场景、时间、景别及用户自定义变量，不扩展新的矩阵界面。
- 明确优先级：角色外观、产品外形等稳定特征保持；本帧指定的景别、机位、时间等可变项覆盖相应共同默认值。
- 对无法自动协调的描述冲突显示具体提示，避免同时发送“固定半身”和“本帧全身”等相反要求。

**验收**：同一场景的雨夜／清晨、特写／全身在最终发送内容中可以区分；无变量的旧帧仍可正常生成；提示词预览与发送内容一致。

**涉及位置**：`public/series-engine.js`、帧编译和预览。

### 2.2 修复矩阵组合计算

**改动范围**

- 正确计算所有有效变量轴的组合总量。
- 返回的每种组合都包含全部轴，达到显示上限时再截取完整组合。
- 不为显示前 200 项而先构造全部巨大组合。
- 组合匹配不依赖对象字段插入顺序；同一组合重复建帧时跳过已有项。
- 删除后新增变量轴不会产生重复 ID。

**验收**：24 × 24 × 2 显示总量 1,152，前 200 项均含三个变量；重复建帧不增加重复项；改变变量轴排列不丢失已有匹配。

**前置**：2.1。此步不增加批量计费调用。

## 6. 阶段三：把版本和生成条件固定下来

### 3.1 分离风格草稿与已采用设定

**改动范围**

- 编辑进入草稿，显示明确的未应用状态。
- 点击应用后，才生成新版本并参与后续任务。
- 提供放弃草稿；刷新和重新打开后可以恢复草稿，但不能默默将其作为已采用版本。
- 从主题提炼的结果先作为草稿展示，用户检查后应用。
- 统一保存相关文案，修正“保存为新手版本”等表述。

**验收**：未应用的修改不改变生图提示词；应用后版本号只增加一次；放弃、刷新和切换项目行为明确；既有系列的当前设定完整保留。

### 3.2 保存可追溯的风格版本

**改动范围**

- 每个已应用版本保存完整设定快照。
- 生成结果记录实际使用的版本，运行中修改风格不改变该结果归属的版本。
- 显示哪些已出图画面使用较早版本，允许查看区别，不自动重生成。
- 本步只做版本查看和选择生成版本，复杂可视化差异比较后置。

**验收**：旧结果能找到对应设定；修改新版本不改写旧快照；导出导入后关系不丢失。

**前置**：3.1；存储升级按第 11 节执行。

### 3.3 增加系列自己的生成参数

**改动范围**

- 系列显示并保存模型、尺寸、画质、返回格式；凭据继续使用现有设置，不写入系列包。
- 新系列从创作页复制一次初始参数；旧系列首次采用独立参数时明确展示当前值。
- 支持主动从创作页更新参数，避免后台联动。
- 单次任务和批次启动时固定参数、风格版本及参考图绑定；后续修改只影响新任务。
- 缺少可用凭据或模型能力不匹配时，生成前定位问题。

**验收**：切换创作页尺寸不改变已有系列；批次中途改设置不影响当前批次；结果能查看实际提示词、模型、参数和参考图清单；记录和导出不含密钥。

**前置**：1.1、3.1。批次里的“上一帧”可在前一帧完成后解析，但必须记录最终实际采用的资源。

## 7. 阶段四：保留结果，改善批量任务

### 4.1 保存同一帧的生成历史

**改动范围**

- 重生成新增结果，保留旧结果；旧数据的单一结果作为第一条历史记录读取。
- 支持切换采用版本、查看大图和手动清理未采用版本。
- 被其他帧引用的结果不能直接删除，展示受影响帧。
- 明确画廊收藏的是哪个生成版本；切换采用版本不悄然覆盖已收藏的副本。
- 并排比较作为本步第二个小交付，先完成历史保存和切换。

**验收**：重生成失败保留原图；版本切换不调用 API；旧版本引用仍有效；清理不影响画廊和白板副本。

**前置**：1.3、3.2。

### 4.2 修正批次检查、计数和失败重试

**改动范围**

- 生成前按帧检查提示词、参数、参考图缺失、数量与大小。
- 区分成功、失败、跳过、取消；没有发请求的帧不计作成功。
- 支持仅重试指定失败帧；保留暂停、停止后续任务的清晰语义。
- 暂停状态禁止插入另一项生成任务，避免任务被跳过但进度增长。
- 将现有“取消”文案解释为“当前帧结束后停止”；立即中止与供应商计费状态处理另行评估。

**验收**：混合有效、无效和失败帧时统计准确；失败重试不重发成功帧；暂停期间没有意外新请求；停止后续任务保留已完成结果。

### 4.3 保存批次并支持恢复

**改动范围**

- 使用已有 `runs` 保存目标帧、任务快照、进度、结果和错误。
- 重新打开后提供未完成批次列表，以及继续未提交项的入口。
- 刷新、断线时正在请求但结果未知的项标为“结果待确认”，不自动重新发送。
- 依次交付“持久化记录”和“恢复操作”，不与并发生成一起开发。

**验收**：关闭页面保留已完成结果；恢复只提交明确尚未提交的项；未知结果有独立状态；继续前可以查看数量与本次参数。

**前置**：3.3、4.2。

## 8. 阶段五：处理原文与参考资料

### 5.1 先让读取范围透明

**改动范围**

- 显示拆帧实际读取的条目、字符范围和截取情况。
- 为长条目提供选择章节或片段的方式，避免默认只读开头。
- 生图引用改用用户确认的相关摘录，展示将发送的摘录；长度不足时不能悄然截掉关键约束。
- 修正提炼缓存的导出说明：未实现完整导出前，准确标明实际内容。

**验收**：用户能确认模型读到了什么；位于长文末尾的选中片段能进入拆帧输入；原文保持完整。

### 5.2 再增加长文分段拆帧

**改动范围**

- 复用现有分块提炼能力，先做章节摘要和情节顺序，再分配帧数。
- 帧关联原文条目及片段范围，支持回查来源。
- 可重试失败片段，成功片段复用缓存；修改原文或文本服务配置后正确失效。
- 先展示拆帧草稿，确认后再加入大纲，不自动替换已有帧。

**验收**：长文后半段关键事件可进入帧清单；帧顺序与来源可核对；部分失败有明确提示；确认拆帧与生成图片是两个独立动作。

**前置**：1.2b、5.1。

## 9. 阶段六：逐项改善画面工作区

本阶段以前面稳定的数据能力为基础。先改一个工作区，不一次替换五个标签。

### 6.1 增加图片联系表视图

- 在现有大纲内新增列表／联系表切换，保留列表入口。
- 卡片突出图片、顺序、标题、采用版本和生成状态；点击再打开详情。
- 缩略图不裁掉用户检查角色、服装和产品外形所需的信息。
- 统一“生成中、失败、已出图、旧设定版本”等状态显示。

**验收**：两种视图操作同一批帧、共用选择状态；切换不丢输入；桌面和手机均无横向溢出。

### 6.2 增加编排操作

- 分三次小交付：先上下移动，再复制／在当前位置插入，最后拖动排序。
- 使用稳定帧 ID，顺序变化不改变素材和结果归属。
- 显示编号随顺序更新；画廊既有副本不被后台改写。
- 明确“上一帧参考”是固定引用还是跟随顺序，显示实际来源，避免排序后无声变化。

**验收**：移动、插入、复制和刷新后顺序一致；复制帧不会误用同一个任务 ID；已有参考关系可解释。

### 6.3 精简设定表单和术语

- “圣经”改为“系列设定”，“档案”改为“原文与设定”，“图库”明确为“参考素材”。
- 设定页先展示风格、主体、参考图、画幅；专业镜头和调色参数折叠。
- “偏离分”改为画面差异参考，说明其衡量颜色、亮度和结构；允许标记有意变化。
- 主导航是否最终合并为“画面／系列设定／素材／批量变体”，留到本步使用验证后决定。

**验收**：原有功能仍有明确入口；预览内容不因折叠丢失；界面不把视觉差异分数表述为人物身份判断。

## 10. 阶段七：分别补齐三种用途

这一阶段是后续路线，完成前面的修复后再细化字段和界面。不会一次引入三套独立项目结构。

### 7.1 同角色／同风格图集：先做角色卡

- 首先支持一个角色卡：名称、稳定外观、服装、参考图；帧选择角色后自动带入。
- 再扩展多角色，明确每张参考图对应谁，不把多人外观混成一段共同设定。
- 区分保持不变的身份特征与本帧允许变化的表情、姿势、服装。

**验收**：角色设定和参考图在提示词中对应清楚；更改共同角色设定后显示受影响帧；未指定角色的旧项目正常使用。

### 7.2 连续故事／分镜／绘本：再做连续性

- 帧引用角色、场景和关键道具，补充情节节点与本帧变化。
- 提供相邻帧对照，检查参考素材、服装状态、场景和镜头变化。
- 先做人工可核对的连续性信息，再评估模型辅助检查，不自动判定作品是否合格。

**验收**：用户可追踪角色／道具在各帧的状态；镜头变化不会被共用设定强行锁死；只修改局部帧即可继续创作。

### 7.3 产品／海报：最后补产品卡和批量变体

- 先做产品卡：外形、颜色、标识、材质、不可修改项和参考图。
- 再做海报文字、留白、版式与变量组合预览；准确文字内容与风格描述分开记录。
- 基于修复后的矩阵选择要生成的组合，不默认全量生成。
- 默认从预览和单张确认进入批量任务。

**验收**：变量不会覆盖锁定的产品特征；待生成组合可核对；文案和版式进入真实请求；图片中文字效果另需真实模型验收。

## 11. 数据兼容、验证和每步交付要求

### 数据兼容

- 旧系列、旧帧和旧系列包持续可读取；新增字段提供默认值。
- 旧单一结果迁移为一条生成历史，保留原资源 ID 和引用。
- 历史上从未保存过的风格版本无法恢复，明确标为缺少历史快照，不用当前设定伪造旧版本。
- 导入前校验记录、大小和引用关系；系列包的跨表写入用同一事务，失败整体回滚。
- 导出随功能逐步补齐风格版本、参数、生成记录和必要缓存，记录包版本；始终排除 API Key。
- 修改数据库版本前，用独立浏览器配置准备旧数据副本，验证迁移、导出和恢复。不要清空现有浏览器数据来完成升级。
- 暂不设置自动清理生成历史，先提供明确的手动清理和引用保护。

### 验证方式

| 变更 | 最低验证要求 |
| --- | --- |
| 提示词与矩阵 | 不同变量真实改变发送内容；组合完整；无变量旧帧兼容 |
| 异步与任务隔离 | 延迟模拟响应，验证切换、重复提交、目标删除和失败返回 |
| 存储与版本 | 事务失败、旧数据读取、刷新恢复、导入导出及断网图片读取 |
| 批量任务 | 混合成功／失败／跳过／未知状态，验证统计及恢复不重复提交 |
| 页面与编排 | 真实浏览器操作、键盘和手机布局；验证已有输入与选择保留 |
| 三种创作用途 | 各保留一个小型示例项目；结构正确后再评估真实模型效果 |

每次先运行相关检查，再运行所需回归。没有新改动或失败原因时不反复扩大测试。涉及跨页收藏关系时验证画廊和白板副本，其他步骤不顺带修改这两个模块。

### 每次交付说明

1. 本次只完成了哪个编号。
2. 用户可见行为及相关数据变化。
3. 实际跑过的检查及结果。
4. 旧数据兼容与恢复情况；是否存在尚未覆盖的场景。
5. 下一项建议以及发现后需要调整的范围。

## 12. 推荐推进顺序

1. **最近一轮**：0.1 → 1.1。先恢复测试，再修复已复现的生成串项目；两步分别交付。
2. **第二轮**：1.2a → 1.2b → 1.3。补齐其他异步归属和结果保存。
3. **第三轮**：2.1 → 2.2。让矩阵变量和组合正确生效。
4. **第四轮**：3.1 → 3.2 → 3.3。建立明确的设定版本与请求条件。
5. **第五轮**：4.1 → 4.2 → 4.3。保留生成历史，再完善批量任务。
6. **后续**：5.1 → 5.2 → 6.1 → 6.2 → 6.3，随后逐项进入 7.1、7.2、7.3。

轮次用于整理先后关系，不代表一次要完成整轮。近期不承诺全部路线的固定工期；前两步完成后，根据实际改动量和新发现再估算下一轮。
